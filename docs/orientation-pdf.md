# Buyer Walk Orientation PDF (RED 2.1.39, 2026-09-22)

## Evidence and scope

The Beaumont BWT DocumentButton names the exact `DR Horton - New Home Orientation Form Beaumont.pdf` template in sibling `Inspections/Documents`. It is an actual builder form, not generated by RED. Archived INSPECT BWT reports store completed forms in Attachments.FileData; their DocumentButton.Value can remain blank. Filenames use the template stem followed by a house/date suffix. The current read-only archive probe found 47 reports: 28 Corpus Christi, 12 Louisiana West, 6 North Central Texas, and 1 Beaumont. The live MyList fixture now has two attachments, so fresh-template tests remove attachments only in a temporary copy, retaining current INS data.

RED now exposes a compact Orientation-only control group. Existing documents and Plan Check controls remain in place. BWT, New Home Orientation names, and the exact Buyer Walk name qualify. Read-only inspections cannot open an editable session.

1. Open Orientation PDF opens an identified embedded attachment first. If several match, select explicitly.
2. With no attachment, RED reads only that exact safe template filename. Missing or corrupt templates fail with an error. There is no file picker or manual PDF import fallback. RED never guesses another region's form or downloads an INS-specified URL.
3. Edit the per-inspection `LocalAppData/RED/OrientationPdf/<path-hash>/<session-id>/Orientation.pdf` copy in the Windows-associated application. If that application cannot edit PDFs, use a PDF editor; RED does not provide one.
4. Save AND close the external editor, then tap Save PDF to INS. This button's No cancels that save, keeps the session, and does not exit the report.
5. Close, report-save/reset, navigation and both updater paths offer Yes (save PDF and continue), No (discard PDF session and continue), and Cancel (stay). No clears session ownership immediately after best-effort cleanup; a locked or missing working file cannot trap the user. Ordinary report changes keep their existing save safeguards. RED cannot see an external application's unsaved in-memory edits; no process-exit or watcher claims are made.

The explicit PDF save writes the active INS through the existing guarded, atomic SurgicalSaveService. Opening/prefilling does not stage or dirty the INS, and ordinary autosaves do not capture PDFs. Failed explicit saves roll back only PDF staging, leaving working bytes and unrelated edits available for retry. Locked/missing/invalid PDFs or external INS conflicts block Yes/save, never No/discard. Failed write candidates retain recovery-copy behavior. Late changes after a successful save still block completion, retaining the session. Cleanup remnants are not automatically reopened or imported.

## Fresh-template autofill

OrientationPdfForm maps the actual known AcroForm names for Beaumont, Corpus Christi, North Central Texas and Louisiana West. It prefers current customer item values (name, phone, email), uses Contact/ContactNumber fallback, and maps serials by item name rather than fixed row number. Project, address, lot, block and DateInspected use the current model. Date formatting preserves the source calendar date/offset, not the machine timezone. Empty, None and null sentinels are omitted. Existing embedded PDFs bypass autofill completely.

Only recognized existing text fields change. Unknown fields, buttons/checkboxes, page content, field flags, default appearance/font resources and interactivity stay intact. The implementation uses PDFsharp dictionaries rather than its typed TextField renderer, which would recreate appearances with a different font. Changed text fields/widgets lose only their stale /AP; /NeedAppearances requests regeneration using the template's existing /DA and /DR. PDFsharp reopen assertions prove values persist; an independent MuPDF render shows the filled values and confirms the PDF remains editable. This is not a claim that Windows PDF-XChange/Adobe has been launched on macOS.

## Preservation

Only a session-owned, indexed attachment patch is authorized. The original token must still match before replacement; arbitrary model attachment changes are not persisted. Metadata and unrelated attachments remain unchanged. FileData is replaced; a non-null ReducedFileData derivative is invalidated because it no longer matches the full PDF. Item answers and unknown document fields are not invented. Date-like metadata remains literal JSON text, avoiding Newtonsoft's automatic timezone/type conversion. Plan Check retains its existing append-only gate.

## Tests

From repository root on macOS with .NET 10 runtime:

    python3 tests/generate_orientation_lifecycle_probe.py
    DOTNET_ROLL_FORWARD=Major dotnet run --project tests/OrientationPdfHarness
    python3 tests/orientation_pdf_static_test.py
    python3 tests/generate_save_lifecycle_probe.py
    dotnet run --project tests/SaveLossHarness -p:RollForward=Major
    python3 -m unittest discover -s tests -p '*test.py'
    dotnet build InspectionEditor.csproj -c Debug -r win-x64 --self-contained true

Optional arguments to OrientationPdfHarness: current BWT INS path, exact template PDF path, Archive directory, optional external evidence directory. These are read-only source probes; all writes use temporary copies. No user INS/PDF fixtures are tracked or packaged. Tests compare independent INS mappings with real archived fields from all four families and byte-exact save/reopen with metadata preservation. The generated UI probe executes production FinishOrientationEditing, explicit Save, and update preparation with only WPF UI/save callbacks stubbed. Existing lifecycle/save/recovery tests remain separate.

Publish only with the normal private generated AI provider present and guard enabled:

    dotnet publish -c Release -r win-x64 --self-contained true -o <external-evidence>/publish

Do not run scripts/publish-release.sh during delegated preparation: it publishes to GitHub. Version/date come from InspectionEditor.csproj. Never package private provider source, settings, user INS files, licenses, recovery or userdata.
