# Buyer Walk Orientation PDF (RED 2.1.38)

## Evidence and scope

The supplied Beaumont BWT INS has an empty Attachments array, but item 15847 (2.28) is a DocumentButton with Template `DR Horton - New Home Orientation Form Beaumont.pdf`. That exact PDF exists in the sibling `Inspections/Documents` directory. It is an actual builder form, not generated by RED. Archived INSPECT BWT reports store completed forms in Attachments.FileData; their DocumentButton.Value remains blank. Their filenames use the template stem followed by a house/date suffix.

RED now exposes a compact Orientation-only control group. Existing documents and Plan Check controls remain in place. BWT, New Home Orientation names, and the exact Buyer Walk name qualify. Read-only inspections cannot open an editable session.

1. Open Orientation PDF opens an identified embedded attachment first. If several match, select explicitly.
2. With no attachment, RED copies the exact filename from INS metadata out of the sibling Documents directory. Missing templates trigger an explicit import dialog. RED never guesses another region's form or downloads an INS-specified URL.
3. Edit the per-inspection `LocalAppData/RED/OrientationPdf/<path-hash>/<session-id>/Orientation.pdf` copy in the Windows-associated application. If that application cannot edit PDFs, use a PDF editor; RED does not provide one.
4. Save AND close the external editor, then tap Save PDF to INS. If using Save As, tap Import PDF and select the saved copy before saving to INS. Import never edits/deletes its source.
5. Close, report-save/reset, navigation and both updater paths require explicit editor completion, even if the INS was otherwise clean. RED cannot see an external application's unsaved in-memory edits; no process-exit or watcher claims are made.

The explicit PDF save writes the active INS through the existing guarded, atomic SurgicalSaveService. Other ordinary saves also capture a valid working copy, but do not end the PDF editing session. Locked/missing/invalid PDFs or external INS conflicts keep the report/session open. Failed write candidates retain the existing recovery-copy behavior. Working copies are only cleaned after explicit completion and a successful INS save; late changes block cleanup. Crash/failed-cleanup remnants can be recovered by importing from the displayed working path. They are not silently deleted on startup.

## Preservation

Only a session-owned, indexed attachment patch is authorized. The original token must still match before replacement; arbitrary model attachment changes are not persisted. Metadata and unrelated attachments remain unchanged. FileData is replaced; a non-null ReducedFileData derivative is invalidated because it no longer matches the full PDF. Item answers and unknown document fields are not invented. Date-like metadata remains literal JSON text, avoiding Newtonsoft's automatic timezone/type conversion. Plan Check retains its existing append-only gate.

## Tests

From repository root on macOS with .NET 10 runtime:

    dotnet run --project tests/OrientationPdfHarness -p:RollForward=Major
    python3 tests/orientation_pdf_static_test.py
    python3 tests/generate_save_lifecycle_probe.py
    dotnet run --project tests/SaveLossHarness -p:RollForward=Major
    python3 -m unittest discover -s tests -p '*test.py'
    dotnet build -c Debug -r win-x64

Optional arguments to OrientationPdfHarness: real empty BWT INS path, exact local template PDF path, archived BWT INS with an attachment. These are read-only probes; no user fixtures are tracked or packaged. Synthetic tests exercise byte fidelity and failure behavior, not PDF rendering.

Publish only with the normal private generated AI provider present and guard enabled:

    dotnet publish -c Release -r win-x64 --self-contained true -o <external-evidence>/publish

Do not run scripts/publish-release.sh during delegated preparation: it publishes to GitHub. Version/date come from InspectionEditor.csproj. Never package private provider source, settings, user INS files, licenses, recovery or userdata.

## Native Windows smoke gate

Still requires a Windows/Surface Pro smoke test: launch/layout/touch, real default PDF association, editor Save/Close and Save As, edit/reopen byte comparison, locks/conflicts, close/navigation/update cancellation, and BAT/UAC install. macOS cross-build and linked production harnesses do not execute WPF or Windows PDF editors. INSPECT upload/server acceptance and form-field autofill are not claimed; RED stores the established attachment schema without proprietary autofill.
